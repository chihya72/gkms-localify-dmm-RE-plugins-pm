# gkms-dlss5 0.3.0-alpha.2

插件 ID：`pm.dlss5`。作者：`pm`。旧 `gkms.dlss5` 是不同的安装条目，安装本包前请先停用旧包；旧参数可从配置的 `settings["gkms.dlss5"]` 复制到 `settings["pm.dlss5"]`。

面向 Gkms SDK 2.0.4 / API 2、DX11 学马客户端的实验性 DLSS 5 Neural Rendering 插件。游戏保持 DX11，模型使用插件私有 DX12 设备。

此版本接入用户指定的 OptiScaler_DLSSNR / RenoDX 核心色彩管线。已验证构建、独立 GPU 执行、颜色重建、缩放、热更新和捕获；实际游戏画质仍须通过同帧图像评估，不能将接口成功或像素改变当作品质提升。

## 0.3 新增移植与适配

- 模型尺寸 25–200%。超过 100% 时先放大模型输入，模型输出经可分离区域平均、Catmull-Rom 双三次、Lanczos2 或 Lanczos3 缩回原尺寸。输入和输出使用相同缩小滤镜，回传两者差异到完整代理图，避免缩放本身吞掉原图细节。四种滤镜是 DX11 适配实现，不代表参考仓库所有缩放后端已移植。
- 色彩强度扩展到 0–4，明暗保护到 1–8；低分辨率支持经典合成和匹配差异回传选择。
- 新增显示模型结果开关；关闭时显示原图，模型仍在运行，便于同帧比较。关闭神经渲染才停止模型计算。
- 冻结输入：保留原始颜色和可用深度、清零冻结帧运动矢量；修改强度、曝光、曲线、模型尺寸时仍使用同一张快照。关闭冻结恢复实时；目标尺寸或格式变化时重新捕获。游戏本身和后续 UI 不暂停。
- 对比支持保持比例的完整画面并排、可移动分界擦除、两侧交换、1–2 倍并排缩放、ORIG/NR 标签。并排缩放 1 会留黑边以保持比例，2 会裁切。标签大小暂固定。
- 实时调试视图：模型输入、模型原始输出、放大差异。截图仍保存未经对比分界和调试覆盖的四阶段图。
- 从 PostProcessPass.m_Depth 取同帧同相机的可用深度，支持 R32、R16、R24 深度读取并转为模型 R32_FLOAT，跟随模型尺寸和 Y 翻转。日志 `depth=connected` 才表示已传递；资源不支持或不存在时跳过，不伪造深度。元数据入口和独立 GPU 传递已验证，实际游戏纹理及视觉效果尚待启动后验证。

当前并非整个 OptiScaler 的完整移植。尚未接入真实游戏曝光纹理、曝光缓冲扫描、多点曝光校准、快捷键绑定、所有缩小滤镜及标签尺寸控制；没有移植 DLSS/FSR/XeSS 替换、帧生成、原生 Vulkan 等整个 OptiScaler 功能。已有自动白点是 P90 场景亮度估算，不等同于参考仓库的曝光跟随。没有新增肤色提亮。

## 处理流程

1. 在 FinalBlitPass.ExecutePass 的原命令缓冲内读取最终拷贝的真实颜色和同帧同相机运动矢量。
2. 保留原始线性颜色；可选 sRGB 输入解码。当前游戏的最终拷贝源上下颠倒，默认先转正后送模型，同时翻转运动矢量采样位置与 Y 分量，合成写回时恢复游戏纹理方向。原图独立保存，不参与反复反馈。
3. 手动白点、EV 或可选分块峰值 P90 自动白点归一化；暗场保持有效值，变化平滑跟随。
4. 使用参考着色器的柔和高光、Neutwo 或混合可逆曲线，进行 sRGB 编码，模型输入 alpha 固定为 1。
5. 区域平均降采样；模型默认按边长 0.5 倍运行，运动矢量同步重采样并换算像素尺度。
6. NR 风格、强度、光照/结构/皮肤和遮罩在创建模型前设置。每次参数更新验证新模型后替换旧会话。
7. 使用参考实现的匹配残差回传、双分支亮度合成、OkLab 色相修正和明暗倍率保护，把模型变化合成回完整原图，保留原始 alpha。
8. 可选左右对比；可保存原图、编码后的模型输入、模型原始输出和最终合成四张同帧 BMP。

核心着色器直接来自 [OptiScaler_DLSSNR](https://github.com/Dagherbou/OptiScaler_DLSSNR/blob/dlss-neural-rendering/OptiScaler/shaders/dlssnr/precompile/dlssnr.hlsl)，其中色彩合成与可逆代理来自 RenoDX。与旧版本直接传入/写回颜色不同，本版本执行完整的编码、模型和合成链。源码和许可证随安装包提供，见 THIRD_PARTY.md。

## 安装与使用

旧版升级需先退出游戏再替换文件。安装目录不变，已有参数由宿主 profile.json 保留。插件总启停/升级仍需重启；参数与配置页的增强开关支持运行中保存应用。

本机模型目录：`D:\chinosk6\gkms-dlss5\out`。`nvngx_dlssnr.dll` 是独立下载的社区兼容模型，未打入 ZIP；`nvngx.dll_dlssnr.dll` 是调用辅助模块，必须留在插件目录。

初始验证设置：模型分辨率比例 0.5、白点 1、EV 0、色彩桥接 0、合成强度 1、色彩混合 0.5、明暗保护 2、输入编码 0。原来保存的模型强度/遮罩等设置会继续保留。

- **模型分辨率比例**：0.25–2；1 为全尺寸，超过 1 是超采样。2 倍边长处理约四倍像素，显存和耗时都会明显增加；4K 场景建议先验证 1.25，不能把独立小纹理的 2 倍测试当作 4K 显存保证。
- **合成强度**：模型变化写回原图的比例；0 为原图精确旁路，不代表模型停止计算。要停止模型计算请关闭增强开关。
- **强度范围**：对齐 OptiScaler，模型内部、光照、结构与合成支持 0–2；大于 1 会加强处理，不保证画质更好。皮肤支持 -1（跟随结构强度）至 2。默认和已存设置仍保持原值。
- **色彩混合**：0 保留游戏原色相，通过亮度携带模型变化；1 使用模型完整颜色；1–4 进一步加强色彩，可能过饱和。
- **白点与 EV**：控制送入模型的曝光；默认手动白点 1。自动白点会增加低频测量开销，不能在黑屏里可靠估计场景尺度。
- **色彩桥接**：0 柔和高光合成；1 Neutwo 合成；2 Neutwo 模型直出；3 混合曲线合成；4 混合曲线模型直出。2/4 绕过合成比例/色相保护，属于实验比较路径。
- **输入编码**：当前最终拷贝路径默认线性 0。仅在确认输入已经编码成 sRGB 时使用 1。
- **修正模型画面上下方向**：当前游戏开启，0.2.0-alpha.1 的实机模型输入截图确认场景倒置。此选项同时处理输入方向、运动矢量和输出还原；正常显示的游戏画面不应因此翻转。保存的四张对比图使用转正后的模型方向。
- **风格与预设**：依赖具体运行库；默认 0，非默认选项的效果/支持情况不作保证。
- **画面对比**：默认左原图、右最终合成、中央黄色竖线；可改方式、位置、缩放和交换两侧。Ctrl+U 隐藏面板后查看。调试视图作用于 NR 一侧，截图不包含这些覆盖。
- **保存一次同帧对比图**：开启并保存后，每 30 帧检查输入，连续四次不接近全黑时保存一次，避免刚出加载黑屏就捕获背景。每次重新应用参数会重置一次捕获机会。文件放在宿主提供的插件 StorageDirectory，日志给出 `capture=nr-...` 前缀。4K 可能产生约数十 MiB 文件及一次明显读取停顿。

## 日志与验证

`Settings applied #N` 表示配置已在一帧中执行完成；`Settings rejected` 表示候选配置失败、原会话保留。异步应用失败时磁盘配置仍是新值，请修正后重新保存。

`model=WxH` 为模型实际尺寸；前面的 WxH 为游戏颜色尺寸。`white_point` 为实际使用的归一化白点，`codec` 为曲线模式。`bridge_ms` 包括转换、模型、合成和同步，不能当作单独模型 GPU 时间。

左右对比时，每 300 帧在最终合成与原图之间采样 64×64 点，记录 delta_mean / delta_max / delta_gt1_255_pct。它们是纹理数值差异，不是画质分数，也不包含黄色对比线；已合成在场景里的 UI 仍可能被包含。

捕获图同帧、同相机，BMP 以 sRGB 预览显示：original/final 在相同显示变换下比较；model-input/model-output 显示模型所见与返回的编码图。HDR 超过显示范围的值在 BMP 中裁剪，不能用它测量完整 HDR 动态范围。

已通过：像素精确桥接与 alpha 保留；三种工作比例；自动白点；曲线 0/1/3；预设 0/1；连续热更新后后续帧；取消/失败回退/成功重试；代理范围与不透明 alpha；恒等模型的颜色恢复；零合成强度原图旁路；GPU/CPU 差异统计一致；四张捕获图保存。实际画质和时序稳定性仍需游戏图像验证。

alpha.2 增加上下不对称图案、空间变化的有符号运动矢量测试，验证输入转正、运动采样及 Y 符号、输出方向恢复、透明度保留，并覆盖线性/sRGB 输入和普通/左右对比写回。模型恒等输出经过实际写回仍恢复原场景。

0.3 新增验证：1.25、1.5、2 倍真实模型处理；四种滤镜；缩放和翻转后的深度逐像素比对；超采样恒等模型最大误差 0.000488281；冻结输入不随实时画面变化且跨参数替换保留；冻结运动归零；显示原图和恢复实时；移动/交换分界、并排比例、缩放、标签与调试视图。测试启用 D3D11/D3D12 调试层检查错误。

## 构建

需要 PowerShell 7、.NET SDK 8+、VS 2022 C++ x64 和 Windows SDK。

在本插件文件夹中执行以下命令，将 `SdkFeed` 改为存放 RE SDK 包的目录。可以单独编译，无需编译照片替换插件。

```powershell
$parameters = @{ SdkFeed = 'D:\PluginWork\sdk-feed'; Test = $true }
& .\Build.ps1 @parameters
if (-not $?) { throw 'Build or tests failed' }
```

真实模型测试（不启动游戏）：

```powershell
$test = Join-Path 'D:\chinosk6\gkms-dlss5\out' 'NativeTests.exe'
[string[]]$arguments = @('D:\chinosk6\gkms-dlss5\out', 'D:\chinosk6\gkms-dlss5\out')
& $test @arguments
if ($LASTEXITCODE -ne 0) { throw "NR tests failed: $LASTEXITCODE" }
```

产物：`out\gkms-dlss5-0.3.0-alpha.2.zip`，包含对应源码 `source.zip`、GPL-3.0 LICENSE 与第三方声明，不含 NVIDIA 模型。

`NativeTests.exe` 在运行库目录、已有输出目录后还可接受第三个参数：本插件保存的 32-bit BMP 绝对路径。此模式分别重放原方向、Y 翻转、加强、全尺寸模型、混合曲线、关闭自动遮罩六种配置，各 30 帧，保存 `replay-*` 四张图。它只比较同一静态 SDR 预览的参数影响，运动为零，不能代替真实 HDR 或游戏时序验证。

## 已知范围

当前使用传统 URP ExecutePass，输入要求同尺寸、非 MSAA 的颜色与运动纹理；深度是可选输入。尚未加入 RenderGraph-only、HUD 独立遮罩、多遍模型堆叠、帧生成或超分替换。这里的光照增强是 NR 图像处理，不会为游戏增加真实的光追/GI 几何数据。

仍使用同步 GPU 桥接。首次创建和热更新可能停顿，替换期间新旧模型资源短暂共存；半尺寸模型降低计算量但不保证特定帧率。已合成的 UI、透明物体运动、切镜和卡通材质仍须实测。
